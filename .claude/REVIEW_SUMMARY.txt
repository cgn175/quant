[CRITICAL] Issue #1: Missing Fee & Slippage Deduction in PnL
  File: internal/execution/engine.go, Lines 154-158
  
  PROBLEM:
    PnL calculation doesn't account for trading fees or slippage:
      pnl = (order.FilledPrice - entryPrice) * size
    
    Engine has FeePercent and SlippageBP config but never uses them.
  
  IMPACT:
    - ALL reported PnL values are INFLATED by 0.5-2%+ per trade
    - Backtesting shows +5% returns when actual is +2.8%
    - Risk management decisions based on false equity
    - Example: $100k account, 2 trades/day, 0.1% fees = $2 daily loss ignored
  
  SEVERITY: BLOCKS LIVE TRADING
    If deployed without fix, bot will overestimate profitability and
    take larger positions than appropriate for risk profile.
  
  FIX: Add fee/slippage deduction (see PHASE6_FIXES.md Issue #1)
    netPnL = (priceDiff * size) - entryFees - exitFees - exitSlippage
  
  EFFORT: 10 minutes

[HIGH] Issue #2: Position State Race Condition
  File: engine.go (Lines 94-126) + manager.go (Lines 115-135)
  
  PROBLEM:
    Engine and Manager track positions independently with no synchronization.
    Two signals could both pass CanOpenPosition() and open duplicate positions.
  
  EXAMPLE:
    t=100ms: Signal A arrives, passes CanOpenPosition() check
    t=101ms: Signal B arrives, also passes check (A hasn't updated state yet)
    t=102ms: Engine executes order for A, Manager registers position
    t=103ms: Engine executes order for B, but position already exists!
  
  IMPACT:
    - Overlapping positions on same symbol
    - Corrupted position state
    - Potential liquidation risk
  
  FIX: Make OpenPosition() method synchronous (see Issue #2 in PHASE6_FIXES.md)
       1. Call rm.CanOpenPosition() first
       2. Execute order
       3. Call rm.OpenPosition() - atomic registration
  
  EFFORT: 30 minutes

---

[HIGH] Issue #3: Model Inference Data Race
  File: predictor.go, Lines 76-103
  
  PROBLEM:
    p.inputTensor.GetData() returns pointer to shared buffer.
    Multiple goroutines can write to same tensor simultaneously.
    ONNX may not be thread-safe for concurrent inference.
  
  IMPACT:
    - Corrupt predictions (feature from goroutine A mixed with B)
    - Silent failures - no error, just wrong probabilities
    - Hard to debug: intermittent issues, varies with timing
  
  FIX: Keep mutex but validate output, ensure single accessor (see Issue #3)
  
  EFFORT: 15 minutes

---

[HIGH] Issue #4: Order.FilledPrice Undefined
  File: engine.go, Lines 155, 157, 164
  
  PROBLEM:
    Code references order.FilledPrice for PnL calculation,
    but never validates it's actually set by executor.
    If executor returns order with FilledPrice=0, PnL becomes 0.
  
  IMPACT:
    - Silent trade loss: trade marked as break-even when it lost money
    - Position sizing affected: equity tracking wrong
  
  FIX: Validate order was accepted before using (add checks in OpenPosition)
  
  EFFORT: 10 minutes

---

[HIGH] Issue #5: Daily Loss Limit Race Condition
  File: manager.go, Lines 105-110
  
  PROBLEM:
    checkDailyReset() is called while holding RLock but modifies state:
    
      func (m *Manager) CanOpenPosition() {
          m.mu.RLock()          // Read lock
          defer m.mu.RUnlock()
          m.checkDailyReset()   // RACE: writes dailyPnL, dailyResetTime
      }
  
    Also called from GetDailyPnL() with RLock.
    Multiple goroutines can reset simultaneously → lost updates.
  
  IMPACT:
    - Daily loss limit not properly enforced
    - Could trade past daily loss cap
    - PnL tracking inconsistent
  
  FIX: Use exclusive Lock (not RLock) in CanOpenPosition and GetDailyPnL
       This prevents concurrent resets.
  
  EFFORT: 5 minutes

---

[HIGH] Issue #6: GetAllPositions Returns Unsafe Pointers
  File: manager.go, Lines 173-182
  
  PROBLEM:
    Returns pointers to internal Position structs.
    Caller can modify without going through manager:
    
      positions := manager.GetAllPositions()
      positions[symbol].Size = 999  // Corrupts internal state!
  
  IMPACT:
    - Breaks encapsulation
    - Can corrupt position data
    - Inconsistent state
  
  FIX: Return deep copies (copy Position value, not pointer)
  
  EFFORT: 5 minutes
